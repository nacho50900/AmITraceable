[[section-glossary]]
== Glosario

[cols="1,3", options="header"]
|===
| Término | Definición

| OSINT
| Open Source Intelligence. Disciplina de recopilar y analizar
  información disponible públicamente (redes sociales, registros
  públicos, etc.) para obtener conclusiones sobre una persona o
  entidad.

| Deanonimización
| Proceso de identificar a una persona concreta a partir de datos
  aparentemente anónimos o dispersos, correlacionando patrones (estilo
  de escritura, horarios, metadatos).

| RGPD
| Reglamento General de Protección de Datos (UE 2016/679). Marco legal
  europeo que regula el tratamiento de datos personales; motiva las
  decisiones de "sin persistencia" y "consentimiento explícito" de este
  proyecto.

| OAuth 2.0
| Protocolo estándar de autorización que permite a un usuario conceder
  acceso limitado a sus datos en una plataforma (Reddit, Instagram) a
  una aplicación de terceros, sin compartir su contraseña.

| `access_token`
| Credencial temporal emitida por el servidor OAuth de una plataforma
  tras el consentimiento del usuario, usada para autenticar peticiones
  a su API en nombre de ese usuario.

| `state` (parámetro OAuth)
| Valor aleatorio generado antes de redirigir al usuario a la
  plataforma de autorización, verificado al recibir el `callback`, para
  prevenir ataques CSRF sobre el flujo OAuth.

| Fingerprinting de escritura / Stylometry
| Análisis del estilo lingüístico de un texto (longitud de frase,
  vocabulario, puntuación, uso de emojis) con el objetivo de
  caracterizar o identificar a su autor.

| TF-IDF
| Term Frequency - Inverse Document Frequency. Técnica estadística para
  extraer las palabras/expresiones más distintivas de un conjunto de
  textos, usada en este proyecto para las `top_keywords` del
  fingerprint.

| Type-Token Ratio
| Métrica de riqueza de vocabulario: proporción entre palabras únicas
  (types) y palabras totales (tokens) en un texto.

| PII (Personally Identifiable Information)
| Información que permite identificar directa o indirectamente a una
  persona (ubicación, ocupación, rutina, en el contexto de este
  proyecto).

| k-anonimato
| Propiedad de un conjunto de datos en la que cada combinación de
  características (edad, sexo, ubicación...) es compartida por al menos
  *k* individuos. En este proyecto se usa como marco conceptual para
  estimar cuánta gente en España comparte lo que el usuario ha declarado
  explícitamente sobre sí mismo, o -- solo para la edad, y con un umbral
  de confianza propio -- lo que se ha podido estimar por tramo a partir
  de pistas indirectas del texto (`scoring/k_anonymity.py`) — cuanto más
  bajo el número resultante, más fácil sería, en teoría, identificar a
  esa persona a partir de esas características.

| Proporción condicionada
| Porcentaje de población que comparte un rasgo, calculado CRUZANDO ese
  rasgo con otra variable ya conocida de la misma persona (sexo, edad,
  nivel de estudios), en vez de usar la proporción marginal general.
  Ejemplo: `SPORT_PRACTICE_BY_SEX` da "qué % de HOMBRES practica
  fútbol", más preciso que "qué % de la población total practica
  fútbol" cuando ya se sabe que la persona es hombre. `practica_deportiva`
  prueba varias en cascada (sexo > edad > nivel de estudios > marginal,
  ver ADR-37) sin combinarlas nunca entre sí, porque no existe un cruce
  publicado a más de una variable a la vez.

| Rasgo físico manual
| Atributo visible (color de ojos, de pelo, tono de piel) que el
  pipeline automático nunca infiere -- ni de texto ni de imagen -- por
  tratarse de un dato especialmente protegido (categorización por
  características raciales/étnicas, art. 9 RGPD). El usuario puede
  declararlo él mismo desde el dashboard (`ManualTraitsSelector.tsx`);
  se suma al estrechamiento de población vía
  `POST /api/analyze/recalculate` y se marca con `source = "manual"`
  para distinguirlo visualmente de los rasgos que sí detecta el sistema
  (ver ADR-34).

| Estudios
| Carrera universitaria concreta que la persona nombra explícitamente
  ("estudié Medicina"), campo `estudios` (`STUDIES_DISTRIBUTION`).
  DISTINTO de "Nivel de estudios" (más abajo): este campo requiere una
  titulación nombrada, no cubre a quien solo dice "tengo el
  bachillerato" o "no tengo estudios" -- para eso está `nivel_estudios`.

| Nivel de estudios
| Nivel de formación MÁXIMO completado (superior / 2ª etapa de
  secundaria / 1ª etapa de secundaria o inferior -- clasificación
  CNED-2014/ISCED del INE), campo `nivel_estudios`. DISTINTO de
  "Estudios" (arriba): alguien puede tener nivel "superior" sin haber
  nombrado ninguna carrera (p. ej. "tengo el título de FP grado
  superior"), y nombrar una carrera concreta implica automáticamente
  nivel "superior" sin declaración aparte (ver ADR-38).

| INE (Instituto Nacional de Estadística)
| Organismo público español responsable de las estadísticas oficiales
  (Censo, Padrón, Encuesta de Población Activa...). Fuente de las
  distribuciones agregadas de población usadas por el estimador de
  k-anonimato (`data/ine_reference.py`).

| Server-Sent Events (SSE)
| Tecnología web para enviar actualizaciones desde el servidor al
  cliente sobre una única conexión HTTP de larga duración, unidireccional
  (servidor -> cliente). Usada en `GET /api/analyze/{platform}/stream`
  para reportar el progreso del análisis en tiempo real.

| Embedding
| Representación numérica (vector) de un dato complejo (una imagen, un
  texto) en un espacio donde la distancia entre vectores refleja
  similitud semántica/visual. Usado en este proyecto para comparar fotos
  por similitud visual (DINOv2).

| DINOv2
| Modelo de visión por computador (Meta AI) que extrae *embeddings* de
  imágenes sin necesidad de etiquetas, usado en este proyecto para
  representar cada foto antes de buscar las más parecidas en el índice
  de referencia.

| VQA (Visual Question Answering)
| Tarea de visión-lenguaje en la que un modelo responde en texto a una
  pregunta sobre el contenido de una imagen. Usada en este proyecto
  (`vision/scene_analysis.py`) para extraer aficiones, actividades y
  señal de pareja de cada foto -- a diferencia de DINOv2, que no
  "entiende" el contenido, solo compara similitud visual.

| Moondream2
| Modelo de visión-lenguaje (VQA) pequeño (~1.8B parámetros), ejecutado
  localmente vía `transformers` en este proyecto para analizar el
  contenido de las fotos de Instagram, sin llamar a ningún servicio
  externo (ver ADR-17).

| FAISS (Facebook AI Similarity Search)
| Librería para búsqueda eficiente de vecinos más cercanos entre
  vectores de alta dimensión. Usada para encontrar, dado el *embedding*
  de una foto, las imágenes más parecidas del índice de referencia de
  España.

| OSV-5M (OpenStreetView-5M)
| Dataset público de investigación con millones de imágenes de calle
  georreferenciadas de todo el mundo, usado (filtrado solo a España)
  como base del índice de geolocalización de este proyecto.

| Comunidad autónoma
| División administrativa española de primer nivel (17 comunidades + 2
  ciudades autónomas), un escalón por encima de la provincia. En este
  proyecto es el nivel de ubicación que se usa cuando ni el texto ni la
  imagen permiten identificar una provincia concreta sin inventar
  información (p. ej. "vivo en Canarias", que agrupa las provincias de
  Las Palmas y Santa Cruz de Tenerife) -- ver `data/ine_reference.py` y
  ADR-9.

| EXIF
| Metadatos incrustados en un archivo de imagen (fecha, modelo de
  cámara, y opcionalmente coordenadas GPS) en el momento de tomar la
  foto. En este proyecto se comprueba como atajo antes de estimar la
  ubicación por similitud visual (ver `vision/geolocation.py`), aunque
  en la práctica casi nunca está presente en fotos servidas por
  Instagram, que elimina el EXIF al subir las imágenes.

| LLM (Large Language Model)
| Modelo de lenguaje de gran escala. En este proyecto, Mistral AI se usa
  automáticamente (sin acción explícita del usuario) para dos funciones
  independientes: generar un veredicto y conclusiones en lenguaje natural
  a partir del informe ya calculado, y complementar la detección de
  autodeclaraciones en texto — sin entrenamiento ni ajuste fino propio en
  ninguno de los dos casos, ver ADR-10, ADR-13 y ADR-14.

| Portabilidad de datos (RGPD Art. 20)
| Derecho de una persona a recibir sus datos personales en un formato
  estructurado, de uso común y lectura mecánica. Motiva la función de
  exportación del informe en JSON de este proyecto.

| Cuenta Business / Creator (Instagram)
| Tipos de cuenta profesional de Instagram, requisito de la Instagram
  Platform API — las cuentas personales normales no tienen acceso vía
  API.

| Reddit for Researchers (RFR)
| Programa oficial de Reddit para conceder acceso a su Data API con
  fines de investigación académica, vía solicitud y aprobación previas.

| Responsible Builder Policy
| Política de Reddit (nov. 2025) que exige aprobación previa para
  cualquier acceso a su Data API, sustituyendo la creación de apps en
  modo autoservicio.

| SonarCloud / Quality Gate
| Servicio de análisis estático de código en la nube; el "Quality Gate"
  es el conjunto de condiciones (cobertura, duplicación, code smells)
  que un análisis debe cumplir para considerarse aprobado.

| ADR (Architecture Decision Record)
| Formato breve para documentar una decisión de arquitectura: contexto,
  decisión tomada, y consecuencias.

| arc42
| Plantilla estándar (12 secciones) para documentar la arquitectura de
  software, usada como estructura de este documento.

| MVP (Minimum Viable Product)
| Versión mínima de un producto con la funcionalidad justa para ser
  útil y evaluable, usada aquí para justificar la reducción de alcance
  respecto a la propuesta original.

| `SocialPost` / `SocialProfile`
| Modelo de datos propio de este proyecto (no un término estándar de la
  industria): representación neutra de un post/perfil de cualquier
  plataforma soportada, con los campos `group` y `score` reinterpretados
  según el origen (ver <<section-concepts>>).

| CI/CD
| Continuous Integration / Continuous Deployment. Automatización de
  tests, análisis de calidad y despliegue en cada cambio de código,
  implementado en este proyecto con GitHub Actions.

| Prometheus / Grafana
| Prometheus: sistema de recolección de métricas por *scraping*.
  Grafana: herramienta de visualización de esas métricas en dashboards.

| Pictograma (isotype chart)
| Representación visual de una proporción usando repetición de un
  icono simple (un icono = una porción de la magnitud representada), en
  vez de un gráfico numérico abstracto. Usado en este proyecto para
  mostrar cuánta población comparte una característica detectada
  (`PopulationPictogram.tsx`): un monigote turquesa frente a N negros.

| Proxy inverso (reverse proxy)
| Servidor que recibe peticiones en nombre de otro servicio y se las
  reenvía, devolviendo la respuesta como si la hubiera generado él
  mismo. En este proyecto, el Nginx de la webapp actúa de proxy inverso
  hacia el backend, para que ambos compartan un único origen de cara al
  navegador (ver ADR-12).

| `lifespan` (FastAPI)
| Gestor de contexto asíncrono que FastAPI ejecuta al arrancar y al
  apagar la aplicación, usado en este proyecto para precargar el modelo
  de geolocalización antes de aceptar peticiones (ver ADR-15), en vez de
  esperar a la primera petición que lo necesite.

| TFG
| Trabajo de Fin de Grado.
|===
