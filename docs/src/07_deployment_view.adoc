=== Infraestructura nivel 1: entornos

[cols="1,2,2", options="header"]
|===
| Entorno | Cómo se levanta | Uso

| Desarrollo local (sin Docker)
| `uvicorn app.main:app --reload --port 3000` (backend, dentro de un
  venv Python) + `npm run dev` (frontend, Vite en puerto 5173)
| Desarrollo día a día; permite hot-reload en ambos lados.

| `docker-compose up --build` desde la raíz del repo
| Prueba del sistema completo tal como se desplegaría, incluida

| Ejecución de tests + análisis SonarCloud en cada push/PR a `main`.

| Build y publicación de imágenes Docker de `backend` y `webapp` en GHCR

  `ghcr.io/nacho50900/amitraceable-webapp`).

=== Infraestructura nivel 1: despliegue con Docker Compose

[source]
----
+------------------------------------------------------------------------+
|                         Docker host                                     |
|                                                                           |
|  red "monitor-net" (bridge)                                             |
|                                                                           |
|  +-----------+   +-----------+   +--------------+   +-------------+      |
|  |  webapp   |-->|  backend  |   |  prometheus  |   |   grafana   |      |
|  | (nginx,   |   | (uvicorn) |   |              |   |             |      |
|  |  proxy)   |   | :3000     |   | :9090        |   | :9091->3000 |      |
|  | :80       |   +-----------+   +--------------+   +-------------+      |
|  +-----------+         |                |                  |            |
|        |                |                |                  |            |
|        |          [ volúmenes: ./backend/data (índice FAISS),            |
|        |            ./backend/data/hf_cache (caché de modelo) ]          |
+--------|----------------|----------------|------------------|-----------+
         |                |                |                  |
    localhost:8080   localhost:3000   localhost:9090     localhost:9091
----

Motivación::
Cada componente en su propio contenedor, en la misma red interna
(`monitor-net`) para que Prometheus pueda hacer *scrape* de
`backend:3000/metrics` sin exponerlo públicamente más que a través del
propio backend. `webapp` es además el único punto de entrada HTTP de
cara al navegador para todo lo demás: su Nginx hace de proxy inverso
hacia `backend` bajo el mismo origen (rutas `/auth/*`, `/api/*`), lo que
permite que un único túnel de desarrollo (Cloudflare) apuntando solo al
puerto de `webapp` sirva también, transparentemente, la autenticación y
la API (ver ADR-12 y <<section-solution-strategy>>). El puerto 3000 del
backend sigue expuesto al host directamente, útil para depurar contra
`/docs` sin pasar por el proxy.

Mapeo de bloques a infraestructura::
[cols="1,2", options="header"]
|===
| Contenedor | Building block(s) que aloja

| `webapp`
| SPA de React compilada (`vite build`), servida como estáticos por
  Nginx, que también actúa de proxy inverso hacia `backend`. Se
  construye con `VITE_API_URL` vacío a propósito (rutas relativas, ver
  `webapp/nginx.conf`) -- solo tendría sentido un valor absoluto si se
  sirviera sin ese proxy delante.

| `backend`
| Backend FastAPI completo (todos los módulos descritos en
  <<section-building-block-view>>). Construido con
  `--build-arg WITH_GEOLOCATION=true` por defecto en `docker-compose.yml`
  (instala `torch`/`faiss`/`transformers`/`timm`/`einops`/`pyvips-binary`,
  ver `requirements-vision.txt`) para que tanto la geolocalización como el
  análisis de contenido visual de fotos funcionen de verdad -- pese al
  nombre heredado del flag, ya no activa solo la geolocalización (ver
  ADR-17). Monta dos volúmenes: el índice FAISS
  (`./backend/data`) y la caché de modelos de Hugging Face
  (`./backend/data/hf_cache`, para no volver a descargar el modelo en
  cada reinicio).

| `prometheus`
| Recolección de métricas expuestas en `backend:3000/metrics`
  (`prometheus-fastapi-instrumentator`).

| `grafana`
| Dashboards sobre las métricas anteriores.
|===

=== Infraestructura nivel 2: runner de CI (GitHub Actions)

Motivación::
Reproducir el entorno de tests sin depender de credenciales reales de
Reddit/Instagram/Mistral AI: las llamadas a las APIs externas se
mockean con `respx` en los tests, así que el runner no necesita salir a
red externa más que para instalar dependencias y hablar con SonarCloud.

Caché::
`actions/setup-node` y `actions/setup-python` cachean `node_modules`
(vía `package-lock.json`) y la caché HTTP de `pip` (vía
`requirements.txt`/`requirements-dev.txt` como clave), evitando
descargar de cero en cada ejecución si esos ficheros no cambian.
