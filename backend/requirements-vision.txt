# Dependencias del módulo OPCIONAL de geolocalización por imagen (ver
# app/vision/geolocation.py). Deliberadamente fuera de requirements.txt:
# son pesadas (varios cientos de MB) y la mayoría de instalaciones (solo
# Reddit, o Instagram sin el índice FAISS construido) no las necesitan.
#
# OJO: esto NO es solo para poder ejecutar scripts/build_faiss_index.py
# (eso puedes hacerlo fuera de Docker, con tu propio venv). Si quieres que
# el backend desplegado con Docker use de verdad el índice ya construido
# en cada análisis de Instagram, la IMAGEN del backend necesita instalar
# esto también -- ver el ARG WITH_GEOLOCATION en el Dockerfile.
#
# torch: build con CUDA (índice cu121) en vez del build SOLO-CPU que se
# usaba antes -- ver docker-compose.yml (reserva de GPU) y el comentario
# largo en app/vision/scene_analysis.py sobre por qué se fuerza float16
# (no bfloat16) para una GPU Turing (GTX 1650 y similares, compute
# capability 7.5): bfloat16 solo tiene aceleración nativa por tensor cores
# desde Ampere (compute capability >= 8.0) -- en Turing, PyTorch SÍ deja
# usar bfloat16, pero lo emula por software (2-4x más lento que con tensor
# cores reales, no tan catastrófico como la emulación en CPU pero tampoco
# la opción correcta aquí). float16 sí tiene aceleración nativa completa
# desde Volta (compute capability >= 7.0), así que es la opción correcta
# para esta GPU en concreto.
#
# cu121 (CUDA 12.1) en vez de una versión más reciente: es la ventana más
# amplia de compatibilidad de drivers NVIDIA razonablemente recientes sin
# exigir la última versión de CUDA -- ajustar si `nvidia-smi` en el host
# reporta una versión de CUDA distinta y da problemas.
--extra-index-url https://download.pytorch.org/whl/cu121
torch>=2.2,<3.0
# Fijado a la ventana de versiones de transformers/accelerate que existía
# cuando se publicó la revisión de Moondream2 que usamos (_MODEL_REVISION =
# "2025-06-21" en scene_analysis.py, transformers 4.53.0 salió el 26 de
# junio de 2025, apenas 5 días después). Un rango abierto (`<5.0`) coge la
# ÚLTIMA versión 4.x disponible en el momento del build, que a día de hoy
# puede ser más de un año posterior a esa revisión.
#
# OJO -- esto es la mejor aproximación posible sin poder ejecutar el
# modelo real para verificarlo (revisar el historial de
# app/vision/scene_analysis.py: hubo varios intentos previos de arreglar
# esto solo tocando los kwargs de `from_pretrained()`, todos fallidos, con
# variantes del mismo error de "meta tensor"). Hay precedente conocido de
# que este modelo concreto rompe compatibilidad con versiones de
# `transformers` más nuevas que las usadas al publicar cada revisión
# (huggingface/transformers#31782, "Moondream breaks on transformers
# 4.42+", para una revisión distinta y más antigua; y un commit de los
# propios mantenedores en Moondream 3, sucesor de este modelo, titulado
# "Call post_init() in HfMoondream for Transformers 5 compatibility" --
# mismo patrón de fondo, versión más reciente). Si con este rango el error
# de "meta tensor" persiste, el siguiente paso YA NO es afinar más este
# pin -- es probar con `_MODEL_REVISION` apuntando a una revisión más
# antigua del modelo en scene_analysis.py (p. ej. "2025-01-09"), cuyo
# fichero interno de integración con HuggingFace (`hf_moondream.py`, no
# versionado por separado, va empaquetado con cada revisión) puede no
# tener el mismo problema.
# OJO: la justificación original de este rango (compatibilidad con el
# `from_pretrained(device_map=...)` de Moondream2 vía `trust_remote_code`,
# ver el bloque de comentarios de abajo) ya NO aplica -- Moondream2 se
# carga ahora vía `llama-cpp-python`, no `transformers` (ver más abajo).
# Este pin queda solo por y para DINOv2 (geolocation.py), que no usa
# `device_map` en ningún sitio y probablemente toleraría un rango bastante
# más amplio -- no se ha tocado por no introducir un cambio sin verificar
# más en la misma sesión que ya tiene varios sin confirmar (ver
# scene_analysis.py). Revisar si algún día da problemas de compatibilidad
# con una versión más reciente que DINOv2 sí necesite.
transformers>=4.48,<4.54
faiss-cpu>=1.8,<2.0

# en scene_analysis.py). YA NO se instala desde aquí un wheel
# PRECOMPILADO con CUDA (el índice cu130 de `abetlen/llama-cpp-python`
# cargaba el modelo pero moría con SIGILL, exit 132, en cuanto tocaba GPU
# en la GTX 1650 real -- confirmado en producción, 12/9: en CPU pura SÍ
# cargaba bien, así que era específico de ese wheel con CUDA, no de la
# CPU) -- probablemente el wheel no trae código compilado para compute
# capability 7.5 (Turing) entre sus arquitecturas. Se compila ahora desde
# código fuente en el `Dockerfile`
# (`CMAKE_ARGS="-DGGML_CUDA=on" -DCMAKE_CUDA_ARCHITECTURES=75`,
# explícitamente para esta GPU), en una etapa aparte con el toolkit
# completo de CUDA -- ver ese fichero. El wheel resultante se instala ahí,
# no desde este fichero.

# Traducción LOCAL de descripciones de fotos al idioma de la UI (ver
# app/nlp/translation.py, ADR-31) -- MarianMT (Helsinki-NLP/opus-mt-*)
# convertido a formato CTranslate2, en vez de traducir con Mistral (ver
# ADR-30, ya descartado): mucho más ligero en RAM/CPU para este caso
# (frases cortas), sin red ni cuota. Comprobado sin conflictos con
# torch/transformers ya fijados arriba (`pip check` limpio).
#
# ctranslate2: el motor de inferencia en sí -- benchmark oficial de
# OpenNMT para un modelo de este tamaño: ~516MB de RAM en CPU con
# cuantización int8, frente a ~2.3GB si se cargara el mismo modelo con
# transformers+torch directos (por eso NO se reutiliza el `transformers`
# ya instalado arriba para esto).
# sentencepiece: tokenización de los modelos ya convertidos (llevan sus
# propios ficheros source.spm/target.spm) -- mucho más ligera que tirar
# de `transformers` para esto, que es justo lo que se quiere evitar.
#
# NO hace falta para EJECUTAR la traducción con los modelos ya
# convertidos, solo para la CONVERSIÓN inicial (ver
# scripts/convert_translation_models.py, que si acaso se ejecuta una vez,
# fuera de la imagen Docker, con torch/transformers ya presentes en este
# mismo entorno):
#   pip install huggingface_hub  # normalmente ya viene como dependencia
#                                 # transitiva de transformers, arriba
ctranslate2>=4.0,<5.0
sentencepiece>=0.2,<1.0
